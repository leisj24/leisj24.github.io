## 第1章 绪论

### 1.1 数据库系统概述

#### 1.1.1 四个基本概念

- **数据（Data）**：描述事物的符号记录，是数据库中存储的基本对象。**数据与其语义不可分**。
- **数据库（Database, DB）**：长期储存在计算机内、有组织的、可共享的大量数据的集合。
  - 5 个基本特征：① 按数据模型组织描述存储；② 共享；③ 冗余度小；④ 数据独立性高；⑤ 易扩展。
- **数据库管理系统（DBMS）**：位于用户与操作系统之间的一层数据管理软件，是基础软件。
  - 用途：科学地组织和存储数据，高效地获取和维护数据。
- **数据库系统（DBS）**：在计算机系统中引入数据库后的人-机系统，组成 = DB + DBMS（及开发工具）+ 应用系统 + DBA。

#### 1.1.2 数据管理技术的产生与发展

| 阶段 | 时期 | 数据组织 | 特点 |
|---|---|---|---|
| 人工管理 | 50年代中以前 | 应用程序管理 | 不保存、不共享、不独立 |
| 文件系统 | 50年代后期—60年代中 | 文件组织 | 长期保存、共享性差、独立性差 |
| 数据库系统 | 60年代后期至今 | DBMS组织 | 数据结构化、共享性高、独立性好、统一管理与控制 |

#### 1.1.3 数据库系统的特点

1. 数据结构化（最本质的区别）
2. 数据的共享性高、冗余度低、易扩充
3. 数据独立性高（物理独立性 + 逻辑独立性）
4. 数据由 DBMS 统一管理和控制（4 项控制功能：安全性、完整性、并发控制、数据库恢复）

### 1.2 数据模型

#### 1.2.1 概念模型（信息世界）

- 实体（Entity）、属性（Attribute）、码（Key）、域（Domain）、实体型（Entity Type）、实体集（Entity Set）
- 联系（Relationship）三种：**1:1、1:n、m:n**
- **E-R 图**：实体（矩形）、属性（椭圆）、联系（菱形），用直线连接，联系上标注 1、n、m

#### 1.2.2 数据模型组成的三要素

1. **数据结构**：系统的静态特征
2. **数据操作**：动态特征，主要有查询、更新（插入、删除、修改）
3. **数据的完整性约束条件**：一组完整性规则的集合

#### 1.2.3 三大经典数据模型

| 模型 | 出现年代 | 代表系统 | 数据结构 | 联系表示 | 优点 | 缺点 |
|---|---|---|---|---|---|---|
| **层次模型** | 最早 | IBM IMS | 树形 | 1:n（连线表示） | 简单清晰，查询高效 | 多对多表示不自然 |
| **网状模型** | 60年代末 | DBTG/CODASYL | 有向图 | m:n（多双亲） | 直接描述现实 | 结构复杂 |
| **关系模型** | 1970 E.F.Codd | DB2、Oracle、MySQL | 二维表 | 用关系表示 | 概念单一、数学基础、存取路径透明 | 查询效率不如非关系，需查询优化 |

- 层次模型条件：① 有且只有一个根；② 根外结点有且只有一个双亲
- 网状模型条件：① 允许多个结点无双亲；② 允许结点有多个双亲

### 1.3 数据库系统的三级模式结构

#### 1.3.1 型与值；模式与实例

- **型（Type）**：结构和属性的说明
- **值（Value）**：型的具体赋值
- **模式（Schema）**：数据库逻辑结构和特征的描述，相对稳定
- **实例（Instance）**：模式的具体值，随更新操作变动

#### 1.3.2 三级模式结构

| 级别 | 别名 | 描述对象 | 个数 | 定义工具 |
|---|---|---|---|---|
| **外模式** | 子模式、用户模式 | 局部数据的逻辑结构 | 多个 | DDL 子语言 |
| **模式（逻辑模式）** | 概念模式 | 全体数据的逻辑结构 | **唯一** | DDL |
| **内模式** | 存储模式 | 数据的物理结构和存储方式 | **唯一** | DDL |

- 外模式与模式：**一对多**
- 外模式与应用程序：**一对多**（一应用只能用一外模式）

#### 1.3.3 二级映像与数据独立性（核心考点）

- **外模式/模式映像**（每个外模式一个）→ 保证**数据的逻辑独立性**
  - 模式变 → 改映像 → 外模式不变 → 应用程序不变
  - 实现：`CREATE VIEW`
- **模式/内模式映像**（**唯一**）→ 保证**数据的物理独立性**
  - 存储结构变 → 改映像 → 模式不变 → 应用不变
  - 实现：`CREATE INDEX`

### 1.4 数据库系统的组成

- 硬件：足够大的内存、外存，较高的通道能力
- 软件：DBMS、支持 OS、高级语言、开发工具、应用系统
- 人员（4 类）：
  - **DBA**（5 项职责）：① 决定信息内容和结构；② 决定存储结构和存取策略；③ 定义安全性和完整性；④ 监控使用和运行；⑤ 改进和重组
  - 系统分析员/设计人员
  - 应用程序员
  - 用户（偶然/简单/复杂）

## 第2章 关系数据库

### 2.1 关系数据结构及形式化定义

#### 2.1.1 关系

- **域（Domain）**：一组具有相同数据类型的值的集合。
- **笛卡尔积**：$D_1 \times D_2 \times \cdots \times D_n = \{(d_1,\ldots,d_n) \mid d_i \in D_i\}$
  - 元组、分量、基数 $M = \prod m_i$
- **关系**：$D_1 \times D_2 \times \cdots \times D_n$ 的子集，记作 $R(D_1, D_2, \ldots, D_n)$，n 为关系的**目/度**
- **属性**：n 目关系有 n 个属性，必须给每列起名字
- 5 类码（核心考点）：
  - **候选码（Candidate Key）**：能唯一标识元组的最小属性组
  - **简单候选码**：只含一个属性的候选码
  - **主码（Primary Key）**：从候选码中选定一个
  - **主属性（Prime Attribute）**：包含在任意候选码中的属性
  - **非主属性**：不包含在任何候选码中的属性
  - **全码（All-Key）**：关系所有属性才构成候选码
- 三类关系：基本表（基本关系）、查询表、视图表（虚表）

#### 基本关系 6 条性质（必考）

1. 列同质
2. 不同列可出自同一域，但不同属性须不同名
3. 列的顺序无所谓
4. **任意两元组的候选码值不能相同**（即不存在完全相同元组）
5. 行的顺序无所谓
6. **分量必须取原子值**（规范化最基本要求）

#### 2.1.2 关系模式

- 关系模式形式定义：$R(U, D, DOM, F)$
  - R 关系名；U 属性集合；D 属性来自的域；DOM 属性向域的映像；F 属性间的数据依赖
- 简记：$R(U)$ 或 $R(A_1, A_2, \ldots, A_n)$
- **关系模式 vs 关系**：模式静态稳定（型）；关系动态变化（值）

### 2.2 关系操作

- **5 种基本运算**：选择 σ、投影 π、并 ∪、差 −、笛卡尔积 ×
- 其他可推：交（∩）、连接（⋈）、除（÷）
- 关系数据语言分类：关系代数语言（ISBL）；关系演算（元组：ALPHA/QUEL；域：QBE）；兼有：**SQL**
- 关系语言特点：集合操作、表达能力完备、非过程化、系统自动查询优化

### 2.3 关系的完整性

#### 三类完整性约束

| 类别 | 内容 | 谁支持 |
|---|---|---|
| **实体完整性（规则 2.1）** | 主属性不能取空值 | DBMS 自动支持 |
| **参照完整性（规则 2.2）** | 外码或为空，或等于被参照表主码值 | DBMS 自动支持 |
| **用户定义完整性** | 具体应用语义约束（如年龄>0） | 用户定义、DBMS 检查 |

- **外码（Foreign Key）**：F 是 R 的属性组，不是 R 的码，但与 S 的主码 $K_s$ 对应，F 是 R 的外码
  - R 参照关系；S 被参照关系
  - R 与 S 可相同（自参照）；外码不一定与主码同名
- 空值：表示"不知道/不存在/无意义"，**不是 0**

### 2.4 关系代数（高频考点）

#### 传统集合运算（4 个）

- 并 $R \cup S$、差 $R - S$、交 $R \cap S = R - (R - S)$、笛卡尔积 $R \times S$

#### 专门关系运算（4 个）

- **选择 σ_F(R)**：从行的角度，挑出满足条件的元组
- **投影 π_A(R)**：从列的角度，挑出指定列（自动去重）
- **连接 ⋈**：
  - θ 连接：$R \underset{A\theta B}{\bowtie} S$
  - 等值连接：θ 为 "="
  - 自然连接：相同属性组比较且去重
  - **悬浮元组**：自然连接舍弃的元组
  - 外连接：保留悬浮元组并填 NULL（左外、右外、全外）
- **除运算 R ÷ S**：象集 $Y_x = \{t[Y] \mid t \in R, t[X]=x\}$，结果 $\{t_r[X] \mid \pi_Y(S) \subseteq Y_x\}$

#### 关系代数表达式典型例题

- "选修了 2 号课程的学生学号"：$\pi_{Sno}(\sigma_{Cno='2'}(SC))$
- "选修了全部课程的学生学号和姓名"：$\pi_{Sno,Sname}(Student) \bowtie (\pi_{Sno,Cno}(SC) \div \pi_{Cno}(Course))$

## 第3章 关系数据库标准语言 SQL

### 3.1 SQL 概述

#### SQL 的特点（5 点）

1. 综合统一（DDL/DML/DCL 集于一体）
2. 高度非过程化（用户提"做什么"，不指明存取路径）
3. 面向集合的操作方式
4. 同一语法结构提供多种使用方式（独立 + 嵌入式）
5. 语言简洁，9 个核心动词

#### SQL 9 个核心动词

| 功能 | 动词 |
|---|---|
| 数据定义 | CREATE, DROP, ALTER |
| 数据查询 | SELECT |
| 数据操纵 | INSERT, UPDATE, DELETE |
| 数据控制 | GRANT, REVOKE |

#### SQL 支持三级模式

- 外模式：视图 + 部分基本表
- 模式：基本表（Base Table）
- 内模式：存储文件（Stored File）

### 3.2 学生-课程数据库（贯穿示例）

```
Student(Sno, Sname, Ssex, Sage, Sdept)
Course(Cno, Cname, Cpno, Ccredit)
SC(Sno, Cno, Grade, Semester)
```

### 3.3 数据定义

#### 3.3.1 模式

```sql
CREATE SCHEMA <模式名> AUTHORIZATION <用户名>;
DROP SCHEMA <模式名> <CASCADE | RESTRICT>;
```

#### 3.3.2 基本表

```sql
CREATE TABLE <表名>
( <列名> <数据类型> [<列级完整性约束>]
  [, <表级完整性约束> ]
);

ALTER TABLE <表名>
  ADD [COLUMN] <新列名> <数据类型> [完整性约束]
  | ADD <表级完整性约束>
  | DROP [COLUMN] <列名> [CASCADE | RESTRICT]
  | DROP CONSTRAINT <约束名> [RESTRICT | CASCADE]
  | ALTER COLUMN <列名> <数据类型>;

DROP TABLE <表名> [RESTRICT | CASCADE];
```

- 完整性约束：`PRIMARY KEY`、`UNIQUE`、`NOT NULL`、`FOREIGN KEY...REFERENCES`
- 数据类型：CHAR(n)、VARCHAR(n)、INT、SMALLINT、BIGINT、NUMERIC(p,d)、DECIMAL、REAL、DATE、TIME、TIMESTAMP

#### 3.3.3 索引

```sql
CREATE [UNIQUE] [CLUSTER] INDEX <索引名>
ON <表名>(<列名>[ASC|DESC][, <列名>[ASC|DESC]]…);

ALTER INDEX <旧索引名> RENAME TO <新索引名>;
DROP INDEX <索引名>;
```

- **CLUSTER（聚簇索引）**：元组按索引键值物理顺序存储，一表仅一个

### 3.4 数据查询（SELECT）

#### SELECT 总体格式

```sql
SELECT [ALL | DISTINCT] <目标列表达式>, …
FROM <表名或视图名>, …
[WHERE <条件>]
[GROUP BY <列名1> [HAVING <条件>]]
[ORDER BY <列名2> [ASC | DESC]];
```

#### 3.4.1 单表查询

- 查询条件谓词：
  - 比较：=, >, <, >=, <=, !=, <>
  - 范围：BETWEEN ... AND
  - 集合：IN, NOT IN
  - 字符匹配：LIKE '<匹配串>' [ESCAPE '<换码字符>']
    - `%`：任意长度（含 0）字符串
    - `_`：单个字符
  - 空值：IS NULL, IS NOT NULL
  - 多重：AND, OR, NOT（AND 优先级高）
- 聚集函数：COUNT(*)、COUNT/SUM/AVG/MAX/MIN([DISTINCT|ALL] <列>)
  - **空值处理**：除 `COUNT(*)` 外，聚集函数跳过空值
- GROUP BY：分组；HAVING：组过滤
- **WHERE vs HAVING**：WHERE 作用于行；HAVING 作用于组；WHERE 不能用聚集函数

#### 3.4.2 连接查询

1. 等值/非等值连接：`Student.Sno = SC.Sno`
2. 自然连接：去重共同属性
3. 自身连接：必须用别名
4. 外连接：`LEFT/RIGHT/FULL OUTER JOIN ... ON ...`
5. 多表连接

#### 3.4.3 嵌套查询

- 不相关子查询：可改写为连接
- 相关子查询：依赖父查询，反复求值
- 子查询限制：不能用 ORDER BY
- 谓词：
  - `IN / NOT IN`
  - 比较运算符（须保证单值）
  - `ANY / SOME / ALL`（须配比较运算符）
  - `EXISTS / NOT EXISTS`（只返回 true/false，常用 `SELECT *`）

#### ANY/ALL 与聚集函数、IN 的等价转换

|   | = | <> != | < | <= | > | >= |
|---|---|---|---|---|---|---|
| **ANY** | IN | — | <MAX | <=MAX | >MIN | >=MIN |
| **ALL** | — | NOT IN | <MIN | <=MIN | >MAX | >=MAX |

#### EXISTS 实现全称量词与蕴涵

- 全称量词：$(\forall x) P \equiv \neg(\exists x)(\neg P)$
- 蕴涵：$p \rightarrow q \equiv \neg p \lor q$
- "选修了全部课程的学生姓名"（全称）：
  ```sql
  SELECT Sname FROM Student
  WHERE NOT EXISTS (
      SELECT * FROM Course
      WHERE NOT EXISTS (
          SELECT * FROM SC
          WHERE Sno=Student.Sno AND Cno=Course.Cno
      )
  );
  ```

#### 3.4.4 集合查询

- **UNION**（自动去重，UNION ALL 保留）、**INTERSECT**、**EXCEPT**
- 要求：各查询结果**列数相同、对应列类型相同**

#### 3.4.5 派生表查询

子查询可出现在 FROM 中作为派生表使用。

### 3.5 数据更新

```sql
INSERT INTO <表> [(<列>, …)] VALUES (<值>, …);
INSERT INTO <表> [(<列>, …)] <子查询>;

UPDATE <表> SET <列>=<表达式>, … [WHERE <条件>];

DELETE FROM <表> [WHERE <条件>];
```

### 3.6 空值处理（三值逻辑）

- 算术运算：NULL 参与结果为 NULL
- 比较运算：结果为 UNKNOWN
- 逻辑运算：T/F/U 三值
  - T AND U = U；F AND U = F
  - T OR U = T；F OR U = U
  - NOT U = U

### 3.7 视图

```sql
CREATE VIEW <视图名> [(<列名>, …)]
AS <子查询>
[WITH CHECK OPTION];

DROP VIEW <视图名> [CASCADE];
```

- 视图是**虚表**，只存放定义，不存放数据
- 视图作用：① 简化操作；② 多视角；③ 提供逻辑独立性；④ 安全保护；⑤ 清晰表达查询
- **行列子集视图**：从单基本表导出，去掉行/列，保留主码 → **可更新**
- WITH CHECK OPTION：保证更新/插入/删除操作满足视图谓词

#### 视图消解（View Resolution）

1. 有效性检查
2. 转换为对基本表的等价查询
3. 执行

#### 视图不可更新的情况

- 来自多个基本表
- 含表达式或常数列
- 含聚集函数
- 含 GROUP BY
- 含 DISTINCT
- 含嵌套查询且内层 FROM 涉及该视图的基表

## 第4章 数据库安全性

### 4.1 数据库安全性概述

#### 4.1.1 数据库不安全因素

1. **非授权用户对数据库的恶意存取和破坏**
2. **数据库中重要或敏感的数据被泄露**
3. **安全环境的脆弱性**（OS、网络环境）

#### 4.1.2 安全标准简介

| 标准 | 全称 | 颁布 |
|---|---|---|
| **TCSEC（橘皮书）** | Trusted Computer System Evaluation Criteria | 1985 美国国防部 |
| **TDI（紫皮书）** | Trusted Database Interpretation | 1991 |
| **CC** | Common Criteria | 1999 ISO/IEC 15408 |

##### TCSEC 4 组 7 级（由低到高）

| 级别 | 定义 |
|---|---|
| **D** | 最小保护 |
| **C1** | 自主安全保护（DAC） |
| **C2** | 受控的存取保护（细粒度 DAC、审计） |
| **B1** | 标记安全保护（MAC） |
| **B2** | 结构化保护 |
| **B3** | 安全域 |
| **A1** | 验证设计（最高级） |

### 4.2 数据库安全性控制

#### 数据库安全控制模型

用户 → 身份鉴别 → DBMS 存取控制 → OS 安全保护 → DBS 数据加密

#### 4.2.1 用户身份鉴别

1. 静态口令
2. 动态口令
3. 生物特征（指纹、虹膜）
4. 智能卡

#### 4.2.2 存取控制

| 类型 | 描述 | 灵活性 | 安全性 |
|---|---|---|---|
| **自主存取控制 DAC** | 用户对不同对象有不同权限，可转授 | 灵活 | 较低 |
| **强制存取控制 MAC** | 每对象有密级标记，按规则强制访问 | 不灵活 | 较高 |

#### 4.2.3 自主存取控制方法（GRANT/REVOKE）

##### GRANT 语法

```sql
GRANT <权限>[, <权限>]…
ON <对象类型> <对象名>[, <对象类型> <对象名>]…
TO <用户>[, <用户>]…
[WITH GRANT OPTION];
```

- 关系（基本表/视图）权限：SELECT、INSERT、UPDATE、DELETE、REFERENCES、ALL PRIVILEGES
- 属性列：SELECT、INSERT、UPDATE、REFERENCES
- 数据库权限：CREATETAB
- WITH GRANT OPTION：被授权用户可再授权给其他人（**不能授给自己**）

例：
```sql
GRANT SELECT ON TABLE Student TO U1;
GRANT ALL PRIVILEGES ON TABLE Student, Course TO U2, U3;
GRANT SELECT ON TABLE SC TO PUBLIC;
GRANT UPDATE(Sno), SELECT ON TABLE Student TO U4;
GRANT INSERT ON TABLE SC TO U5 WITH GRANT OPTION;
```

##### REVOKE 语法

```sql
REVOKE <权限>[, <权限>]…
ON <对象类型> <对象名>[, <对象类型> <对象名>]…
FROM <用户>[, <用户>]… [CASCADE | RESTRICT];
```

- CASCADE 级联收回（收回 U5 时，U5 授予的 U6 也被收回）
- RESTRICT 限制（若已转授给他人则拒绝收回）

#### 4.2.4 数据库角色（Role）

```sql
CREATE ROLE <角色名>;
GRANT <权限>, … ON <对象> TO <角色>, …;
GRANT <角色1>, … TO <角色2|用户>, … [WITH ADMIN OPTION];
REVOKE <权限>, … ON <对象> FROM <角色>, …;
```

例：
```sql
CREATE ROLE R1;
GRANT SELECT, UPDATE, INSERT ON TABLE Student TO R1;
GRANT R1 TO 王平, 张明, 赵玲;
REVOKE R1 FROM 王平;
GRANT DELETE ON TABLE Student TO R1; -- 角色权限自动扩展给已授该角色的用户
```

#### 4.2.5 强制存取控制方法 MAC

- **主体（Subject）**：DBMS 管理的活动实体（DBMS 进程、用户）
- **客体（Object）**：DBMS 管理的被动实体（文件、表、视图、索引）
- **敏感度标记（Label）**：分若干等级（自高到低）
  - **绝密 TS** > **机密 S** > **可信 C** > **公开 P**
  - 主体的敏感度标记 → **许可证级别**
  - 客体的敏感度标记 → **密级**

##### 两条规则

1. **仅当主体的许可证级别 ≥ 客体的密级时，主体才能"读"客体**
2. **仅当主体的许可证级别 ≤ 客体的密级时，主体才能"写"客体**（防止高密级泄露到低密级）

#### DAC vs MAC

- DAC + MAC 共同实现安全保护：DAC 控制是否能存取数据；MAC 控制能否存取在敏感度上允许的数据
- 通常先 DAC 后 MAC

### 4.3 视图机制提供安全

通过视图机制把要保密的数据对无权用户隐藏。

```sql
CREATE VIEW CS_Student AS
SELECT * FROM Student WHERE Sdept='CS';
GRANT SELECT ON CS_Student TO 王平;
```

### 4.4 审计（Audit）

启用一个专用审计日志（Audit Log），记录所有用户对数据库的操作。

```sql
AUDIT ALTER, UPDATE ON SC;
NOAUDIT ALTER, UPDATE ON SC;
```

- C2 以上要求审计功能
- 审计开销大，DBA 根据需要打开/关闭

### 4.5 数据加密

- **存储加密**、**传输加密**（链路加密 vs 端到端加密）
- DBMS 可调用加密程序，由用户选择加密的字段

### 4.6 其他安全性保护

- **推理控制（Inference Control）**：防止用户从合法获得的低密级数据推理出高密级数据
- **隐蔽信道（Covert Channel）**：通过不直接读/写实现非法信息传递
- **数据隐私保护**：个人数据控制（K-匿名等）

## 第5章 数据库完整性

### 5.1 完整性概述

数据的**正确性**和**相容性**。完整性 vs 安全性：
- 完整性 → 防止数据库中存在不符合语义的数据（防止错误数据）
- 安全性 → 保护数据库防止恶意的破坏和非法的存取

DBMS 完整性功能：
1. 提供定义完整性约束条件的机制
2. 提供完整性检查的方法
3. 违约处理

### 5.2 实体完整性

#### 定义

```sql
CREATE TABLE Student (
    Sno   CHAR(9) PRIMARY KEY,   -- 列级
    Sname CHAR(20) NOT NULL,
    ...
);

CREATE TABLE SC (
    Sno CHAR(9),
    Cno CHAR(4),
    Grade SMALLINT,
    PRIMARY KEY (Sno, Cno)       -- 表级（多属性主键必须表级）
);
```

#### 检查与违约处理

插入或主码列更新时：
1. 检查主码是否唯一 → 不唯一则拒绝
2. 检查主码各属性是否为空 → 任一为空则拒绝

通常使用**主码索引**（B+ 树）来高效检查。

### 5.3 参照完整性

#### 定义

```sql
CREATE TABLE SC (
    Sno CHAR(9),
    Cno CHAR(4),
    Grade SMALLINT,
    PRIMARY KEY (Sno, Cno),
    FOREIGN KEY (Sno) REFERENCES Student(Sno),
    FOREIGN KEY (Cno) REFERENCES Course(Cno)
);
```

#### 违约处理

| 被参照表（如 Student） | 参照表（如 SC） | 违反完整性？ | 违约处理 |
|---|---|---|---|
| 可能破坏 | 插入元组 | 是 | 拒绝 |
| 可能破坏 | 修改外码 | 是 | 拒绝 |
| 删除元组 | | 是 | 拒绝/级联删除/设空值 |
| 修改主码 | | 是 | 拒绝/级联修改/设空值 |

#### 显式指定违约处理

```sql
FOREIGN KEY (Sno) REFERENCES Student(Sno)
    ON DELETE CASCADE       -- 级联删除
    ON UPDATE CASCADE;      -- 级联更新

FOREIGN KEY (Sno) REFERENCES Student(Sno)
    ON DELETE NO ACTION     -- 拒绝
    ON UPDATE CASCADE;

FOREIGN KEY (Sno) REFERENCES Student(Sno)
    ON DELETE SET NULL      -- 置空（外码非主属性才行）
    ON UPDATE CASCADE;
```

- `NO ACTION`（默认）：拒绝执行
- `CASCADE`：级联
- `SET NULL`：置空（外码不能是主属性时使用）
- `SET DEFAULT`：置默认值

### 5.4 用户定义完整性

#### 5.4.1 属性上的约束

```sql
CREATE TABLE Student(
    Sno   CHAR(9) NOT NULL,
    Sname CHAR(20) UNIQUE,
    Ssex  CHAR(2) CHECK(Ssex IN ('男','女')),

```

- `NOT NULL`、`UNIQUE`、`CHECK`

```sql
CREATE TABLE Student(

    Sname CHAR(20),
    Ssex CHAR(2),
    ...,
    CHECK (Ssex='女' OR Sname NOT LIKE 'Ms.%')  -- 元组级约束

```

```sql

```

例：
```sql

```

### 5.7 断言（Assertion）

```sql
CREATE ASSERTION <断言名> CHECK <条件>;
DROP ASSERTION <断言名>;
```

例：每个学生选课总数不能超过 10 门
```sql

    ));
```

### 5.8 触发器（Trigger）

#### CREATE TRIGGER 完整语法

```sql
CREATE TRIGGER <触发器名>
{BEFORE | AFTER} <触发事件> ON <表名>
REFERENCING NEW|OLD ROW AS <变量>
FOR EACH {ROW | STATEMENT}
[WHEN <触发条件>]
<触发动作体>;
```

- 触发事件：INSERT、DELETE、UPDATE[OF <列>]，可用 OR 组合
- BEFORE：在触发事件前激活；AFTER：在触发事件后激活
- FOR EACH ROW：行级触发器；FOR EACH STATEMENT：语句级
- REFERENCING：定义变量名（NEW/OLD ROW，NEW/OLD TABLE）

例 1：行级触发器
```sql
CREATE TRIGGER SC_T
AFTER UPDATE OF Grade ON SC
REFERENCING OLD ROW AS OldTuple, NEW ROW AS NewTuple
FOR EACH ROW
WHEN (NewTuple.Grade >= 1.1*OldTuple.Grade)
INSERT INTO SC_U(Sno, Cno, OldGrade, NewGrade)
VALUES(OldTuple.Sno, OldTuple.Cno, OldTuple.Grade, NewTuple.Grade);
```

例 2：语句级触发器
```sql
CREATE TRIGGER Student_Count
AFTER INSERT ON Student
REFERENCING NEW TABLE AS DELTA
FOR EACH STATEMENT
INSERT INTO StudentInsertLog(Numbers)
SELECT COUNT(*) FROM DELTA;
```

#### 触发器激活、级联与优先

1. 执行 BEFORE 触发器
2. 激活触发器的 SQL 语句
3. 执行 AFTER 触发器
4. 同一表上多个触发器：BEFORE 先于 AFTER；同类型按创建时间先后

#### 删除触发器

```sql
DROP TRIGGER <触发器名> ON <表名>;
```

## 第6章 关系数据理论

### 6.1 问题的提出

#### 不好的关系模式存在的 4 大问题

1. **数据冗余**
2. **更新异常**
3. **插入异常**
4. **删除异常**

#### 数据依赖

- 函数依赖（FD）：1:1 或 n:1
- 多值依赖（MVD）：1:n
- 连接依赖

### 6.2 规范化

#### 6.2.1 函数依赖（FD）

- **定义 6.1**：R(U)，X、Y ⊆ U。对 R 的任意关系 r，不存在两元组在 X 上相等而在 Y 上不等，则 X→Y。
- **平凡 FD**：Y ⊆ X
- **非平凡 FD**：Y ⊄ X
- **完全函数依赖** $X \xrightarrow{F} Y$：X→Y 且对 X 的任意真子集 X'，X'↛Y
- **部分函数依赖** $X \xrightarrow{P} Y$：X→Y 但不完全依赖
- **传递函数依赖** $X \xrightarrow{\text{传递}} Z$：X→Y，Y↛X，Y→Z

#### 6.2.2 码

- **候选码**：K →F U
- **主码**：候选码中选定的一个
- **超码**：K → U（不一定完全）
- **主属性 / 非主属性 / 全码 / 外码**

#### 6.2.3 范式（必背）

$$1NF \supset 2NF \supset 3NF \supset BCNF \supset 4NF \supset 5NF$$

| 范式 | 定义 | 消除什么 |
|---|---|---|
| **1NF** | 分量不可再分（原子值） | — |
| **2NF** | R∈1NF 且每个非主属性完全函数依赖于候选码 | 非主属性对码的**部分**函数依赖 |
| **3NF** | 不存在 X→Y, Y↛X, Y→Z 使非主属性 Z 传递依赖 | 非主属性对码的**传递**函数依赖 |
| **BCNF** | 每个非平凡 FD X→Y 中 X 都包含候选码 | 主属性对码的部分/传递依赖 |
| **4NF** | 每个非平凡多值依赖 X→→Y 中 X 都含码 | 非平凡且非函数依赖的多值依赖 |

#### 6.2.7 多值依赖（MVD）

- 定义 6.9：X →→ Y 当且仅当对任一关系 r，给定 (x, z)，Y 的值仅依赖 x 而与 z 无关
- 平凡 MVD：Z = U − X − Y = ∅
- 性质：对称性、传递性、FD 是 MVD 的特例

### 6.3 Armstrong 公理系统

#### 三条基本公理

1. **自反律 A1**：若 Y ⊆ X ⊆ U，则 X→Y
2. **增广律 A2**：若 X→Y，则 XZ→YZ
3. **传递律 A3**：若 X→Y，Y→Z，则 X→Z

#### 三个推论

- **合并律**：X→Y, X→Z ⇒ X→YZ
- **伪传递律**：X→Y, WY→Z ⇒ XW→Z
- **分解律**：X→Y, Z⊆Y ⇒ X→Z

#### 函数依赖闭包 F⁺

- 由 F 出发用 Armstrong 公理推导出的所有 FD 的集合
- Armstrong 公理是**有效的**（正确）和**完备的**

#### 属性集闭包 $X_F^+$

- $X_F^+ = \{A \mid X→A 能由 F 根据公理导出\}$
- **引理 6.2**：$X→Y$ 能由 F 推出 ⟺ $Y \subseteq X_F^+$

#### 算法 6.1（求属性集闭包）

```
X⁽⁰⁾ = X, i=0
循环：
  B = {A | ∃V→W∈F, V⊆X⁽ⁱ⁾, A∈W}
  X⁽ⁱ⁺¹⁾ = B ∪ X⁽ⁱ⁾
  若 X⁽ⁱ⁺¹⁾ = X⁽ⁱ⁾ 或 = U，停止
  否则 i++
```

#### 最小函数依赖集 Fm

满足三条：
1. 每个 FD 右部仅一个属性
2. 不存在 X→A 使 F − {X→A} 与 F 等价（无冗余 FD）
3. 不存在 X→A 其 X 的真子集 Z 使 F−{X→A}∪{Z→A} 与 F 等价（左部无冗余）

**求 Fm 的步骤**：
1. 右部单一化
2. 去除冗余 FD（逐个测试 A ∈ $X_{F-\{X→A\}}^+$）
3. 左部最小化

#### 求候选码（属性分类法）

将属性按 F 分为 4 类：
- **L 类**：仅出现在 FD 左部 → 必在候选码中
- **R 类**：仅出现在 FD 右部 → 不在任何候选码中
- **N 类**：在 FD 中未出现 → 必在候选码中
- **LR 类**：左右都出现 → 可能在候选码

方法：取 L+N 类属性 X，若 $X_F^+ = U$，则 X 是唯一候选码；否则在 LR 中尝试添加。

### 6.4 模式分解

#### 三种分解性质

1. **无损连接性**：$r = \pi_{R_1}(r) \bowtie \pi_{R_2}(r) \bowtie \cdots \bowtie \pi_{R_n}(r)$
2. **保持函数依赖**：$F^+ = (F_1 \cup F_2 \cup \cdots \cup F_n)^+$
3. **既无损连接又保持函数依赖**

#### 算法 6.1 chase 测试（判断无损连接）

构造 k×n 表格，根据 FD 反复修改，直到出现全 a 行即无损连接。

#### 定理 6.2（两表分解判定）

ρ = {R₁, R₂} 无损连接 ⟺ $U_1 \cap U_2 \rightarrow U_1 - U_2 \in F^+$ 或 $U_1 \cap U_2 \rightarrow U_2 - U_1 \in F^+$

#### 算法 6.2、6.3、6.4

- **算法 6.2**：3NF 保持 FD 的分解
- **算法 6.3**：3NF 既无损又保持 FD 的分解
- **算法 6.4**：BCNF 无损连接分解（**不一定**保持 FD）

#### 关键结论

- 3NF：可达到既无损又保持 FD
- BCNF：仅可达无损连接，保持 FD 不一定
- 4NF：仅可达无损连接

- 面向对象方法（OO）
- **统一建模语言 UML**
- 计算机辅助设计法（CASE）

### 7.2 需求分析

#### 任务

- 详细调查、收集和分析用户的应用需求
- 确定系统的边界
- 主要包括：① 信息要求；② 处理要求；③ 安全性和完整性要求

#### 方法

- 调查组织机构总体情况、各部门业务活动情况
- 与用户结合协助确定信息要求和处理要求
- 确定新系统的边界

#### 数据字典（DD）

数据字典是关于数据库中数据的描述，即元数据。包含 5 部分：
1. **数据项**：数据的最小单位（项名、含义、类型、长度、取值范围等）
2. **数据结构**：若干数据项有意义的集合
3. **数据流**：数据结构在系统内传输路径（来源、去向、平均流量等）
4. **数据存储**：数据结构停留或保存的地方
5. **处理过程**：算法概要描述

#### 数据流图（DFD）

由外部实体、加工、数据流、数据存储 4 种元素组成。从顶层逐步细化。

### 7.3 概念结构设计

#### 概念模型的特点

1. 能真实、充分反映现实世界
2. 易于理解
3. 易于更改
4. 易于向各种数据模型转换

#### E-R 模型

- **实体（Entity）**：矩形
- **属性（Attribute）**：椭圆
- **联系（Relationship）**：菱形
- 联系类型：1:1、1:n、m:n
- **三元联系**：3 个实体之间的联系

#### 扩展 E-R 模型

- **ISA 联系**：特殊化/泛化（子类继承父类的属性和联系）
  - 不相交约束 / 重叠约束
  - 完全约束 / 部分约束
- **弱实体（Weak Entity）**：依赖于强实体存在；用双线矩形；标识符部分来自所有者实体
- **聚合（Aggregation）**：联系可以作为另一联系的实体

#### E-R 图设计步骤

1. 选择局部应用，确定中层数据流图作为设计起点
2. 逐一设计**分 E-R 图**（局部）
3. 集成为**总 E-R 图**（全局）

#### 局部 E-R 图集成（合并）

##### 解决 3 类冲突

1. **属性冲突**：
   - 属性域冲突（类型/取值范围/单位不同）
   - 属性取值单位冲突
2. **命名冲突**：
   - 同名异义、异名同义（一物多名）
3. **结构冲突**：
   - 同一对象在不同应用中有不同抽象（实体 vs 属性）
   - 同一实体在不同分 E-R 图中属性组成不同
   - 实体之间的联系在不同分 E-R 图中类型不同

##### 修改和重构

- 消除冗余属性
- 消除冗余联系（如能由其他联系导出的联系）
- 用规范化理论消除冗余

### 7.4 逻辑结构设计

#### E-R 图向关系模型的转换规则

##### 1. 实体的转换
每个实体转换为一个关系模式：实体的属性 → 关系的属性；实体的码 → 关系的码。

##### 2. 联系的转换

| 联系类型 | 转换规则 |
|---|---|
| **1:1 联系** | （a）合并到任一端实体的关系模式中（加另一端的码做外码及联系本身的属性）；（b）也可独立转换为关系模式 |
| **1:n 联系** | （a）合并到 n 端实体的关系模式中（加 1 端的码和联系属性）；（b）独立转换为关系，码是 n 端的码 |
| **m:n 联系** | **必须**独立转换为关系，关系码是两端实体码的组合（联合主键） |
| **3 个或以上实体间的联系** | 独立转换为关系，码是各实体码的组合 |
| **同一实体集内的联系** | 同上规则处理 |

例：学生（学号，姓名）课程（课号，课名），选修联系 m:n
→ 学生(学号,姓名)，课程(课号,课名)，选修(学号,课号,成绩)

#### 数据模型优化

1. 确定数据依赖
2. 消除冗余联系
3. 确定各关系的范式（一般要求 3NF 或 BCNF）
4. **分解和合并**：
   - 水平分解：把元组分入若干关系（按使用频率）
   - 垂直分解：把属性分入若干关系
5. 提高查询效率时可考虑反规范化

#### 设计用户子模式（外模式）

- 使用更符合用户习惯的别名

## 第9章 关系查询处理和查询优化

### 9.1 查询处理 4 阶段

1. **查询分析**：词法、语法分析
2. **查询检查**：合法权、视图转换、安全性/完整性
3. **查询优化**：代数优化、物理优化
4. **查询执行**：代码生成；自顶向下/自底向上

### 9.2 实现查询操作的算法

#### 选择运算

- **全表扫描**：适合小表
- **索引（Hash）扫描**：适合大表、列有索引
  - 主码=值 → 主码索引
  - 比例<10% 用索引扫描，否则全表扫描

#### 连接运算

1. **嵌套循环法**：外表逐元组扫内表全表
2. **排序-合并法**：先排序后顺序合并
3. **索引连接法**：内表建索引，外表用索引查
4. **Hash Join**：划分阶段（小表）+ 试探阶段（大表）

### 9.3 查询优化

#### 9.3.1 代价模型

- 集中式：I/O + CPU + 内存代价（I/O 主要）
- 分布式：增加**通信代价**

#### 9.3.2 代数优化（11 条等价变换规则）

1. 连接、笛卡尔积**交换律**
2. 连接、笛卡尔积**结合律**
3. **投影串接**：$\pi_{A_1\ldots A_n}(\pi_{B_1\ldots B_m}(E)) \equiv \pi_{A_1\ldots A_n}(E)$
4. **选择串接**：$\sigma_{F_1}(\sigma_{F_2}(E)) \equiv \sigma_{F_1 \land F_2}(E)$
5. 选择与投影交换
6. 选择与笛卡尔积交换
7. 选择与并的分配
8. 选择与差的分配
9. **选择对自然连接的分配**
10. 投影与笛卡尔积分配
11. 投影与并分配

#### 9.3.3 启发式优化规则

1. **选择运算尽可能先做**（最基本）
2. 把投影和选择同时进行
3. 把投影同其前后双目运算结合
4. 把某些选择同笛卡尔积结合成连接运算
5. 找公共子表达式

#### 9.3.4 物理优化

- 基于启发式规则的存取路径选择
- 基于代价估算（需统计信息：元组数、不同值个数、选择率、索引层数等）

## 第10章 数据库恢复技术

### 10.1 事务

#### ACID 4 大特性

| 特性 | 内容 |
|---|---|
| **原子性 (Atomicity)** | 操作要么全做要么全不做 |
| **一致性 (Consistency)** | 从一致状态变到另一一致状态 |
| **隔离性 (Isolation)** | 事务之间不相互干扰 |
| **持久性 (Durability)** | 事务提交后改变是永久的 |

#### 事务的 SQL 语句

```sql
BEGIN TRANSACTION
   SQL 语句…
COMMIT     -- 提交
-- 或
ROLLBACK   -- 回滚
```

### 10.2 故障种类（4 类）

| 故障 | 描述 | 恢复方法 |
|---|---|---|
| **事务故障** | 事务未到正常终点 | UNDO |
| **系统故障**（软故障） | 系统重启，事务非正常终止 | UNDO 未完成 + REDO 已完成 |
| **介质故障**（硬故障） | 磁盘损坏 | 重装备份 + REDO |
| **计算机病毒** | 人为故障 | 视情况 |

### 10.3 恢复实现技术

#### 数据转储

| 分类维度 | 类型 |
|---|---|
| **状态** | 静态转储 / 动态转储 |
| **方式** | 海量转储 / 增量转储 |

- 静态转储：转储期间无事务，副本一致
- 动态转储：与事务并发，**必须配合日志**

#### 日志文件

- 内容（以记录为单位）：① 事务标识；② 操作类型；③ 操作对象；④ 旧值；⑤ 新值
- **两条登记原则**：
  1. **登记次序严格按并行事务执行的时间次序**
  2. **必须先写日志再写数据库（WAL: Write-Ahead Logging）**

### 10.4 恢复策略

#### 事务故障（UNDO）

反向扫描日志 → 对每个更新操作执行逆操作 → 直到读到 BEGIN

#### 系统故障（UNDO + REDO）

1. 正向扫描日志，分两队列：
   - REDO 队列：已 COMMIT 的事务
   - UNDO 队列：未完成的事务
2. UNDO 队列反向扫描，逆操作
3. REDO 队列正向扫描，重做

#### 介质故障（重装备份 + REDO）

1. 装入最近后备副本（动态转储须配合日志做 REDO+UNDO）
2. 装入故障发生时刻的日志文件副本，REDO 已完成事务

### 10.5 具有检查点的恢复技术

#### 检查点记录

- 建立检查点时所有正在执行的事务清单（ACTIVE-LIST）
- 这些事务最近一个日志记录的地址

#### 利用检查点的恢复

```
T1 |───|                      检查点前已提交 → 不必 REDO
T2 |───|────|                  检查点前开始，故障前提交 → REDO
T3 |────|──────|---            检查点前开始，故障时未完 → UNDO
T4      |───|                  检查点后开始，故障前提交 → REDO
T5      |─────────|---         检查点后开始，故障时未完 → UNDO
       Tc          Tf
```

### 10.6 数据库镜像

DBMS 自动把整个数据库或关键数据复制到另一磁盘 → 介质故障时可立即用镜像替代。

## 第11章 并发控制

### 11.1 并发控制概述

#### 多事务执行方式

1. 事务串行执行
2. **交叉并发**（单 CPU）
3. **同时并发**（多 CPU）

#### 并发带来的 3 大数据不一致

1. **丢失修改（Lost Update）**：T1 修改被 T2 覆盖
2. **不可重复读（Non-repeatable Read）**：T1 读后 T2 改/删/插，T1 再读不一致（含幻影 Phantom Row）
3. **读"脏"数据（Dirty Read）**：T2 读了 T1 未提交的修改，T1 ROLLBACK

**根源**：并发操作破坏了事务的**隔离性**。

#### 并发控制主要技术

- 封锁（Locking）：商用主流
- 时间戳（Timestamp）
- 乐观控制
- 多版本并发控制（MVCC）

### 11.2 封锁

#### 两种基本锁

| 锁 | 名称 | 含义 |
|---|---|---|
| **X 锁** | 排它锁（写锁） | 只允许加锁者读和修改 |
| **S 锁** | 共享锁（读锁） | 加锁者读，其他人也可加 S 不能加 X |

#### 相容矩阵

| T1\T2 | X | S | — |
|---|---|---|---|
| **X** | N | N | Y |
| **S** | N | Y | Y |
| **—** | Y | Y | Y |

### 11.3 封锁协议（三级）

| 协议 | 加锁规则 | 防止 |
|---|---|---|
| **一级** | 修改前加 X 锁，事务结束才释放 | 丢失修改 |
| **二级** | 一级 + 读前加 S 锁，**读完即释放** | 丢失修改、读脏 |
| **三级** | 一级 + 读前加 S 锁，**事务结束才释放** | 丢失修改、读脏、不可重复读 |

### 11.4 活锁与死锁

#### 活锁

T 永远等待。**解决**：先来先服务。

#### 死锁

互相等待对方持有的锁。

**预防**：
- **一次封锁法**：一次全加锁
- **顺序封锁法**：按预定次序加锁

**诊断与解除**：
- 超时法
- **等待图法**：图中有回路即死锁
- 解除：撤销代价最小的事务

### 11.5 并发调度的可串行性

- **可串行化调度**：结果与某种串行执行结果相同
- 可串行性是并发调度正确性的**唯一**准则
- **冲突可串行化**：不同事务对同一数据的读写或写写不能交换；可通过交换不冲突操作转化为串行调度 → **充分非必要**条件

### 11.6 两段锁协议（2PL）

- **扩展阶段**：只能申请锁，不能释放
- **收缩阶段**：只能释放锁，不能申请
- **定理**：若所有事务都遵守 2PL，则任何并发调度都是可串行化的（**充分非必要**）
- **遵守 2PL 仍可能死锁**

### 11.7 封锁粒度

- 粒度大 → 并发度低、开销小
- 粒度小 → 并发度高、开销大

#### 多粒度封锁与意向锁

3 种意向锁：
- **IS 锁**：后裔拟加 S
- **IX 锁**：后裔拟加 X
- **SIX 锁**：S + IX

#### 意向锁相容矩阵

| T1\T2 | S | X | IS | IX | SIX |
|---|---|---|---|---|---|
| **S** | Y | N | Y | N | N |
| **X** | N | N | N | N | N |
| **IS** | Y | N | Y | Y | Y |
| **IX** | N | N | Y | Y | N |
| **SIX** | N | N | Y | N | N |

#### 锁的强度偏序

$$X > SIX > S \text{ 或 } IX > IS$$

- 申请封锁：自上而下
- 释放封锁：自下而上

### 11.8 事务的隔离级别（SQL 标准）

| 级别 | 丢失修改 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|---|
| 读未提交 | 否 | 是 | 是 | 是 |
| 读已提交 | 否 | 否 | 是 | 是 |
| 可重复读 | 否 | 否 | 否 | 是 |
| 可串行化 | 否 | 否 | 否 | 否 |

### 二、关系代数专题

#### 2.1 必背符号与含义

| 符号 | 名称 | 形式 | 备注 |
|---|---|---|---|
| ∪ | 并 | $R \cup S$ | 同目同属性 |
| − | 差 | $R - S$ | 同目同属性 |
| ∩ | 交 | $R \cap S$ | 可推导 |
| × | 笛卡尔积 | $R \times S$ | (n+m) 目 |
| σ | 选择 | $\sigma_F(R)$ | 横向，按行 |
| π | 投影 | $\pi_A(R)$ | 纵向，按列，去重 |
| ⋈ | 自然连接 | $R \bowtie S$ | 公共属性等值并去重 |
| ⋈_θ | θ连接 | $R \underset{A\theta B}{\bowtie} S$ | 不去重 |
| ÷ | 除 | $R \div S$ | "全部"语义 |
| ▷◁_F | 外连接 | LEFT/RIGHT/FULL | 保留悬浮元组 |

#### 2.2 关系代数书写关键技巧

##### 技巧 1：从查询语句结构入手

- 看到"查询...的..."→ 最外层投影 π
- 看到"...满足条件"→ 选择 σ
- 看到"涉及多张表"→ 连接 ⋈
- 看到"选了**全部**X的"→ 除 ÷

##### 技巧 2：先选择后连接（查询优化思想）

错误：$\pi(\sigma(Student \bowtie SC))$ — 数据量大

正确：$\pi(Student \bowtie \sigma(SC))$ — 先在小表上选择

#### 2.3 经典例题汇总

**示例库**：
- Student(Sno, Sname, Ssex, Sage, Sdept)
- Course(Cno, Cname, Cpno, Ccredit)
- SC(Sno, Cno, Grade)

##### 例 1：查询选修了 2 号课程的学生学号

$$\pi_{Sno}(\sigma_{Cno='2'}(SC))$$

##### 例 2：查询选修了课程名为"数据库"的学生学号和姓名

$$\pi_{Sno, Sname}(Student \bowtie SC \bowtie \sigma_{Cname='数据库'}(Course))$$

##### 例 3：查询不学 1 号课程的学生姓名

$$\pi_{Sname}(Student) - \pi_{Sname}(\sigma_{Cno='1'}(SC) \bowtie Student)$$

##### 例 4：查询至少选修了 1 号和 3 号课程的学生学号

**用除运算**：构造临时表 K = {Cno=1, Cno=3}

$$\pi_{Sno, Cno}(SC) \div K$$

##### 例 5：查询选修了**全部**课程的学生学号和姓名（最经典除运算）

$$\pi_{Sno, Sname}(Student) \bowtie (\pi_{Sno, Cno}(SC) \div \pi_{Cno}(Course))$$

##### 例 6：查询至少选修了学生 95002 所选全部课程的学生学号

$$\pi_{Sno, Cno}(SC) \div \pi_{Cno}(\sigma_{Sno='95002'}(SC))$$

#### 2.4 自然连接 vs 等值连接（必考辨析）

| 维度 | 自然连接 | 等值连接 |
|---|---|---|
| 比较属性 | **必须同名** | 可以不同名 |
| 比较运算 | "=" | "=" |
| 重复列 | **去掉** | **保留** |
| 记号 | $R \bowtie S$ | $R \underset{A=B}{\bowtie} S$ |

#### 2.5 除运算计算步骤（分 4 步）

**例**：求 $R \div S$，R(A, B, C)，S(B, C)

1. 求 $\pi_A(R)$，得到候选 A 值集合
2. 对每个 a，求其象集 $(B,C)_a = \{t[B,C] \mid t[A]=a\}$
3. 求 $\pi_{B,C}(S)$
4. 若 $(B,C)_a \supseteq \pi_{B,C}(S)$，则 a 属于结果

### 三、SQL 综合查询专题

#### 3.1 SELECT 语句执行顺序（重要！）

逻辑执行顺序与书写顺序不同：

```
FROM → ON → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT
```

#### 3.2 经典查询模板

##### 模板 1：聚集 + 分组 + 过滤

```sql
-- 查询平均成绩 ≥ 80 的课程及其平均成绩
SELECT Cno, AVG(Grade)
FROM SC
GROUP BY Cno
HAVING AVG(Grade) >= 80;
```

##### 模板 2：子查询（IN）

```sql
-- 选修了"数据库"课程的学生姓名
SELECT Sname FROM Student
WHERE Sno IN (
    SELECT Sno FROM SC
    WHERE Cno IN (SELECT Cno FROM Course WHERE Cname='数据库')
);
```

##### 模板 3：相关子查询 EXISTS（必考）

```sql
-- 选修了 1 号课程的学生姓名
SELECT Sname FROM Student
WHERE EXISTS (
    SELECT * FROM SC
    WHERE Sno=Student.Sno AND Cno='1'
);
```

##### 模板 4：双重 NOT EXISTS 实现全称（难点）

```sql
-- 选修了全部课程的学生姓名
SELECT Sname FROM Student
WHERE NOT EXISTS (
    SELECT * FROM Course
    WHERE NOT EXISTS (
        SELECT * FROM SC
        WHERE Sno=Student.Sno AND Cno=Course.Cno
    )
);
```

**口诀**："不存在 X，使得 X 与该学生没有选课关系"

##### 模板 5：三重 NOT EXISTS 实现"蕴涵"

```sql
-- 至少选修了 95002 所选全部课程的学生学号
SELECT DISTINCT Sno FROM SC SCX
WHERE NOT EXISTS (
    SELECT * FROM SC SCY
    WHERE SCY.Sno='95002'
      AND NOT EXISTS (
          SELECT * FROM SC SCZ
          WHERE SCZ.Sno=SCX.Sno AND SCZ.Cno=SCY.Cno
      )
);
```

**含义**：不存在课程 y，95002 选了 y，而 SCX 没选 y。

##### 模板 6：自身连接

```sql
-- 查询每门课的间接先修课
SELECT FIRST.Cno, SECOND.Cpno
FROM Course FIRST, Course SECOND
WHERE FIRST.Cpno = SECOND.Cno;
```

##### 模板 7：外连接

```sql
-- 列出所有学生（包括未选课的）及其选课信息
SELECT Student.Sno, Sname, Cno, Grade
FROM Student LEFT OUTER JOIN SC ON Student.Sno=SC.Sno;
```

#### 3.3 SQL 易错点（必看）

##### 易错 1：WHERE 不能用聚集函数

```sql
-- ❌ 错误
SELECT Sno, AVG(Grade) FROM SC
WHERE AVG(Grade) >= 90 GROUP BY Sno;

-- ✅ 正确
SELECT Sno, AVG(Grade) FROM SC
GROUP BY Sno HAVING AVG(Grade) >= 90;
```

##### 易错 2：NULL 比较

```sql
-- ❌ 错误
WHERE Grade = NULL;

-- ✅ 正确
WHERE Grade IS NULL;
```

##### 易错 3：通配符转义

```sql
-- 查询课程名以 "DB_" 开头
WHERE Cname LIKE 'DB\_%' ESCAPE '\';
```

##### 易错 4：聚集函数与 NULL

- `COUNT(*)` 统计所有行（含 NULL）
- `COUNT(列名)` 跳过 NULL
- `SUM/AVG/MAX/MIN` 都跳过 NULL

##### 易错 5：UNION 自动去重

```sql
-- 去重
SELECT … UNION SELECT …;
-- 保留重复
SELECT … UNION ALL SELECT …;
```

#### 3.4 视图三大考点

##### 考点 1：视图消解

```sql
-- 视图
CREATE VIEW IS_Student AS
SELECT Sno, Sname, Sage FROM Student WHERE Sdept='IS';

-- 查询：
SELECT * FROM IS_Student WHERE Sage<20;

-- 消解为：
SELECT Sno, Sname, Sage FROM Student WHERE Sdept='IS' AND Sage<20;
```

##### 考点 2：WITH CHECK OPTION

```sql
CREATE VIEW IS_Student AS
SELECT Sno, Sname, Sage, Sdept FROM Student WHERE Sdept='IS'

-- INSERT 时若 Sdept ≠ 'IS' 会被拒绝（自动检查谓词）
```

##### 考点 3：可更新视图条件（仅行列子集视图可更新）

不可更新的情况：
- 含表达式/常数
- 含聚集函数
- 含 GROUP BY
- 含 DISTINCT
- 来自多个基表
- 含嵌套子查询且内层从基表查询

### 四、规范化与函数依赖专题

#### 4.1 五大核心算法（综合大题必考）

##### 算法 1：求属性集闭包 $X_F^+$

```
输入：属性集 X、函数依赖集 F
输出：X 的闭包

步骤：
1. X⁰ = X，i = 0
2. 在 F 中找所有 V→W，使 V ⊆ Xⁱ
3. Xⁱ⁺¹ = Xⁱ ∪ 所有 W
4. 若 Xⁱ⁺¹ = Xⁱ 或 = U，结束
5. 否则 i++，回 2
```

**例**：F = {AB→C, B→D, C→E, EC→B, AC→B}，求 $(AB)^+$
- 初始 X⁰ = AB
- 用 AB→C, B→D 得 X¹ = ABCD
- 用 C→E 得 X² = ABCDE = U
- 结果：$(AB)^+$ = ABCDE

##### 算法 2：求候选码（属性分类法）

```
1. 将所有属性按 F 分类：L / R / N / LR
2. X = L ∪ N（这些必在候选码中）
3. 若 X⁺ = U，则 X 是唯一候选码
4. 否则在 LR 中选取属性逐个加入 X，再求闭包
   找出所有使闭包 = U 的最小属性组
```

**例**：F = {A→D, E→D, D→B, BC→D, DC→A}
- L 类：C, E
- R 类：（无）
- N 类：P（如有）
- LR 类：A, B, D
- (CE)⁺ = CEABD = U → CE 是唯一候选码

##### 算法 3：求最小函数依赖集 Fm

```
三步：
1. 右部单一化：将 X→YZ 拆为 X→Y, X→Z
2. 去除冗余 FD：逐一测试 A ∈ (X){F-{X→A}}⁺ 则可删
3. 左部最小化：对 X={B1,…,Bn}→A，逐一测试 A∈(X-Bi)⁺ 则用 X-Bi 替换
```

**例**：F = {A→B, AB→C, D→AC, D→B}

- 右部单一化：{A→B, AB→C, D→A, D→C, D→B}
- 去冗余：
  - AB→C：(AB){F-{AB→C}}⁺ = ABCD？是 → 删
  - D→B：(D){F-{D→B}}⁺ = DACB？是 → 删
- 结果：Fm = {A→B, D→A, D→C}

##### 算法 4：判断无损连接（chase 测试 / 表格法）

```
构造 k×n 表：
- k = 分解的关系个数
- n = 总属性个数
- 若 Aj ∈ Ui，第 i 行第 j 列填 aj，否则填 bij

对每个 FD X→Y：
- 找 X 列上相等的所有行
- 修改 Y 列：有 a 用 a；都为 b 用最小下标 b

迭代直到不变。若出现全 a 行 → 无损连接。
```

**两表分解简单判定**：
- $U_1 \cap U_2 \rightarrow U_1 - U_2$ ∈ F⁺ 或
- $U_1 \cap U_2 \rightarrow U_2 - U_1$ ∈ F⁺
- 即：**公共属性是其中一方的候选码**

##### 算法 5：BCNF 无损连接分解

```
ρ = {R}
反复：
  从 ρ 中找出不属于 BCNF 的 Ri
  在 Fi 中找一个 X→A，X 不含码
  分解 Ri 为：
    Si1 = XA
    Si2 = Ui - {A}
  替换 ρ
直到所有 Ri 都属于 BCNF
```

#### 4.2 范式判定决策树

```
1. 关系中分量都是原子值吗？
   否 → 不属于 1NF
   是 → 至少 1NF

2. 找出所有候选码
3. 找出所有非主属性

4. 非主属性 P 部分依赖于某候选码吗？
   是 → 不属于 2NF
   否 → 至少 2NF

5. 非主属性传递依赖于某候选码吗？
   是 → 不属于 3NF
   否 → 至少 3NF

6. 所有非平凡 FD X→Y 中，X 都包含候选码吗？
   是 → 属于 BCNF
   否 → 仅 3NF

7. 所有非平凡 MVD X→→Y 中，X 都包含候选码吗？
   是 → 属于 4NF
```

#### 4.3 综合大题模板

**题型**：给定 R(U, F)，求：(1) 候选码；(2) 范式；(3) 分解到 3NF/BCNF。

**模板**：
1. 用属性分类法求候选码（先标 L/R/N/LR）
2. 判断每个 FD 是否满足 BCNF 要求（左部含码）
3. 找出非主属性的部分/传递依赖
4. 应用算法 6.3 或 6.4 分解

#### 4.4 多值依赖与 4NF

- $X \rightarrow\rightarrow Y$：给定 (x, z)，Y 仅依赖 x
- **MVD 性质**：① 对称性 $X→→Y$ 则 $X→→U-X-Y$；② FD 是 MVD 的特例
- 4NF：非平凡 MVD 的左部必含码

**典型 4NF 反例**：Teaching(C, T, B) — C→→T, C→→B → All-key 是 BCNF 但非 4NF
- 分解：CT(C, T), CB(C, B)

### 五、E-R 模型与数据库设计专题

#### 5.1 数据库设计六步骤

```
需求分析 → 概念设计 → 逻辑设计 → 物理设计 → 实施 → 运维
   ↓         ↓         ↓         ↓        ↓     ↓
```

#### 5.2 E-R 图设计 5 个常见问题

##### 问题 1：判断实体还是属性

**原则**：
- 能再独立描述（多个属性）→ 实体
- 只有单一值且无其他依赖 → 属性

##### 问题 2：联系类型判断

- 1:1 — 一个 A 对应一个 B
- 1:n — 一个 A 对应多个 B；一个 B 对应一个 A
- m:n — 一个 A 对应多个 B；一个 B 对应多个 A

##### 问题 3：弱实体

- 不能独立存在，依赖于父实体
- 用双线矩形表示
- 例：订单的"订单明细"是订单的弱实体

##### 问题 4：自参照联系

- 同一实体集内部的联系
- 例：员工-上级（员工的"管理"联系自参照）

##### 问题 5：三元联系

- 3 个实体之间的联系
- 例：教师-学生-课程的"任课"联系

#### 5.3 E-R 图向关系模型转换（必考）

##### 转换规则总表

| 联系类型 | 转换方法 | 主码 |
|---|---|---|
| 1:1 | 合并到任一端，加另一端的码 | 任一端的码 |
| 1:1 | 或独立成关系 | 任一端的码均可 |
| 1:n | 合并到 n 端，加 1 端的码 | n 端的码 |
| m:n | **必须**独立成关系 | **两端码的组合** |
| 三元联系 | 独立成关系 | 三端码组合 |
| 自参照 | 同上 | — |

##### 转换示例

**E-R 图**：
- 学生（学号，姓名）
- 课程（课号，课名）
- 联系"选修"，m:n，含属性"成绩"

**转换**：
- 学生(学号, 姓名)
- 课程(课号, 课名)
- 选修(学号, 课号, 成绩) — 主码 (学号, 课号)

#### 5.4 局部 E-R 图集成 3 类冲突

| 冲突类型 | 含义 | 解决 |
|---|---|---|
| **属性冲突** | 域、单位不同 | 协商统一 |
| **命名冲突** | 同名异义、异名同义 | 协商统一 |
| **结构冲突** | 同一对象的抽象不同（实体 vs 属性）；同一实体在不同图中属性不同；联系类型不同 | 统一为最复杂的形式 |

### 六、事务、恢复与并发专题

#### 6.1 三大数据不一致辨析

| 类型 | 操作模式 | 三级协议解决 |
|---|---|---|
| **丢失修改** | T1 读 → T2 读 → T1 写 → T2 写（T1 被覆盖） | 一级 |
| **读"脏"数据** | T1 写 → T2 读 → T1 ROLLBACK（T2 读脏） | 二级 |
| **不可重复读** | T1 读 → T2 写 → T1 再读不一致 | 三级 |
| **幻读** | T1 读 → T2 插入/删除 → T1 再读多/少了行 | 可串行化 |

#### 6.2 三级封锁协议对比

| 协议 | X 锁（修改） | S 锁（读取） | 防止 |
|---|---|---|---|
| **一级** | 事务结束释放 | 不加 | 丢失修改 |
| **二级** | 事务结束释放 | 读完释放 | + 读脏 |
| **三级** | 事务结束释放 | 事务结束释放 | + 不可重复读 |

#### 6.3 2PL 与可串行化关系

- **遵守 2PL → 可串行化**（充分非必要）
- 2PL **不要求**一次性加锁，**可能发生死锁**
- 一次封锁法 → 遵守 2PL → 必然无死锁

#### 6.4 可串行化判定（题型）

**给定调度，判定是否可串行化**：

##### 方法 1：找等价串行调度

通过交换不冲突操作（不同事务/不同数据），看能否变成某种串行调度。

##### 方法 2：构造冲突图

- 结点：事务
- 有向边：若 T_i 的操作先于 T_j 的冲突操作，画 T_i → T_j
- **若图无环 → 冲突可串行化**
- 拓扑排序即为等价串行调度

**示例**：
```
T1: R(A) W(A)
T2:        R(A) W(A)
T1:                    R(B) W(B)
T2:                                R(B) W(B)
```
- T1 的 W(A) 先于 T2 的 R(A) → T1 → T2
- T1 的 W(B) 先于 T2 的 R(B) → T1 → T2
- 无环 → 等价串行：T1 → T2 ✓

#### 6.5 死锁判定（等待图）

**等待图**：
- 结点：事务
- 边：T_i → T_j 表示 T_i 等待 T_j

**有环 → 死锁**

#### 6.6 故障恢复流程（必考）

##### 系统故障恢复（含检查点）

```
1. 从重新开始文件找最近检查点位置
2. 由检查点得 ACTIVE-LIST 放入 UNDO-LIST，REDO-LIST 暂空
3. 正向扫描日志到末尾：
   - 新事务 → 加入 UNDO-LIST
   - 已 COMMIT → 从 UNDO-LIST 移至 REDO-LIST
4. UNDO-LIST 反向 UNDO
5. REDO-LIST 正向 REDO
```

##### 介质故障恢复

```
1. 装入最近的后备副本
2. 装入相应的日志文件副本
3. 对已 COMMIT 的事务做 REDO
```

#### 6.7 WAL（Write-Ahead Logging）

**两条登记原则**：
1. 严格按事务执行的时间次序
2. **先写日志，后写数据库**

**为什么**：
- 若先写 DB 而日志未写 → 故障时无法 UNDO → 不一致
- 若先写日志而 DB 未写 → 故障时多做一次 UNDO/REDO → 仍正确

#### 6.8 意向锁使用要点

- 在数据对象上加 S/X 锁 → 先在其**所有上级结点**加 IS/IX
- 例：对元组加 S → 先对所在表加 IS → 先对所在 DB 加 IS

#### 6.9 隔离级别 → 锁协议 对应

| 隔离级别 | 等价于 |
|---|---|
| 读未提交 | 无 S 锁 |
| 读已提交 | 二级封锁 |
| 可重复读 | 三级封锁 |
| 可串行化 | 2PL + 范围锁 |

#### 简答题要点

1. **二级映像与独立性**：
   - 外模式/模式映像：每个外模式一个，模式改时改映像 → 外模式不变 → 应用不变 → 逻辑独立性
   - 模式/内模式映像：唯一，存储结构改时改映像 → 模式不变 → 物理独立性

2. **WHERE vs HAVING**：
   - WHERE 作用于元组（行），是单行过滤
   - HAVING 作用于分组结果（组），可用聚集函数
   - 执行顺序：WHERE → GROUP BY → HAVING

3. **三种连接**：
   - 等值连接：用 "=" 比较，保留所有列
   - 自然连接：要求公共属性同名，去重
   - 外连接：保留悬浮元组并填 NULL

4. **WAL**：① 严格按时间次序；② 先写日志再写数据库。原因：若先写 DB 后写日志，故障时无法恢复（日志无记录）

5. **意向锁**：用于多粒度封锁，避免检查所有下级结点。IS 后裔拟加 S；IX 后裔拟加 X；SIX = S + IX

##### 题 1

1. **关系代数**：
$$\pi_{Sname}(\sigma_{Cname='数据库' \land Grade \geq 90}(S \bowtie SC \bowtie C))$$

```sql
SELECT Sname FROM S, SC, C
WHERE S.SID=SC.SID AND SC.CID=C.CID
```

$$\pi_{SID, Sname}(S) - \pi_{SID, Sname}(S \bowtie SC)$$

```sql
SELECT SID, Sname FROM S
```

```sql
SELECT DISTINCT SID FROM SC SCX
```

##### 题 2

1. **求候选码**：
   - 属性分类：FD = {A→BC, CD→E, B→D, E→A}
     - L 类：（无）
     - R 类：（无）
     - N 类：（无）
     - LR 类：A, B, C, D, E
   - 试 A⁺ = ABCDE = U → A 是候选码
   - 试 B⁺ = BDA = ABD，再 ABD → BCE → ABCDE = U → B 是候选码
   - 试 E⁺ = EA = AE → ABCDE = U → E 是候选码
   - 试 CD⁺ = CDE = CDE → ABCDE → CD 是候选码
   - **候选码：A, B, E, CD**

2. **范式判定**：
   - 主属性：A, B, C, D, E（全是！）
   - 非主属性：（无）
   - 既然没有非主属性，自然满足 3NF
   - 检查 BCNF：FD A→BC 中 A 是码 ✓；CD→E 中 CD 是码 ✓；B→D 中 B 是码 ✓；E→A 中 E 是码 ✓
   - **R 属于 BCNF**

   - 借阅(借阅号, 读者号, 书号, 借阅日期, 归还日期)，主码：借阅号，外码：读者号 → 读者，书号 → 图书

3. **建表 SQL**：
```sql
CREATE TABLE 借阅(
    借阅号 CHAR(10) PRIMARY KEY,
    读者号 CHAR(8) NOT NULL,
    书号 CHAR(10) NOT NULL,
    借阅日期 DATE NOT NULL,
    归还日期 DATE,
    CHECK (归还日期 IS NULL OR 归还日期 >= 借阅日期),

);
```

```sql
CREATE TRIGGER 借书更新库存

```

### 🧠 公式速查卡

#### 关系运算

- 笛卡尔积基数：$M = \prod m_i$
- 并 $R \cup S$；差 $R - S$；交 $R \cap S = R - (R-S)$
- 选择 $\sigma_F(R) = \{t \mid t\in R \land F(t)=\text{真}\}$
- 投影 $\pi_A(R) = \{t[A] \mid t\in R\}$
- 自然连接 $R \bowtie S$（公共属性等且去重）
- 除 $R \div S = \{t_r[X] \mid \pi_Y(S) \subseteq Y_x\}$
- 象集 $Y_x = \{t[Y] \mid t\in R, t[X]=x\}$

#### 完整性规则

- **规则 2.1（实体）**：主属性 A 不能取空值
- **规则 2.2（参照）**：外码 F ∈ {NULL, K_s 已存在的某值}

#### Armstrong 公理

- A1 自反：$Y \subseteq X \Rightarrow X \rightarrow Y$
- A2 增广：$X \rightarrow Y \Rightarrow XZ \rightarrow YZ$
- A3 传递：$X \rightarrow Y, Y \rightarrow Z \Rightarrow X \rightarrow Z$

#### 推论

- 合并：$X \rightarrow Y, X \rightarrow Z \Rightarrow X \rightarrow YZ$
- 伪传递：$X \rightarrow Y, WY \rightarrow Z \Rightarrow XW \rightarrow Z$
- 分解：$X \rightarrow Y, Z \subseteq Y \Rightarrow X \rightarrow Z$

#### 重要等价

- $(\forall x) P \equiv \neg(\exists x)(\neg P)$
- $p \rightarrow q \equiv \neg p \lor q$
- $X \rightarrow Y$ 能由 F 推出 ⟺ $Y \subseteq X_F^+$
- 两表分解无损连接 ⟺ 公共属性是某方候选码

#### 代价估算

- 嵌套循环代价：$\text{cost} = B_r + \lceil B_r/(K-1) \rceil \cdot B_s$
- 全表扫描：$\text{cost} = B$（码=值：B/2）
- 索引扫描（码=值）：$\text{cost} = L + 1$

### 💡 高频考题题型与套路

#### 题型 1：关系代数书写

**套路**：
1. 看"查询..."→ 最外层 π
2. 看"满足..."→ σ
3. 看多表关联 → ⋈
4. 看"全部"→ ÷
5. 看"没有/不"→ −

#### 题型 2：SQL 嵌套查询

**套路（带 EXISTS）**：
- "存在选了..."→ EXISTS
- "没有选..."→ NOT EXISTS
- "选了所有..."→ 双重 NOT EXISTS
- "至少选了 X 选的所有..."→ 三重 NOT EXISTS

#### 题型 3：范式与分解

**套路**：
1. 用 L/R/N/LR 分类 → 求候选码
2. 找主属性 / 非主属性
3. 判定范式（决策树）
4. 应用算法 6.3（3NF）或 6.4（BCNF）分解

#### 题型 4：E-R 图与关系模型转换

**套路**：
1. 找实体（独立的、有多个属性）
2. 找联系（实体之间的关系动词）
3. 标注联系类型（看双向）
4. 转换：m:n 必独立，主码用两端码组合

#### 题型 5：并发调度分析

**套路**：
1. 列出操作时序（带时刻）
2. 标出冲突操作
3. 构造冲突图
4. 判断有无环 → 冲突可串行化？
5. 若有等待 → 等待图判断死锁

#### 题型 6：恢复过程模拟

**套路**：
1. 标出 BEGIN / COMMIT / 故障点 / 检查点
2. 分类事务：
   - 检查点前 COMMIT → 不处理
   - 检查点前开始，故障前 COMMIT → REDO
   - 检查点前开始，故障时未完 → UNDO
   - 检查点后开始，故障前 COMMIT → REDO
   - 检查点后开始，故障时未完 → UNDO

### 🔥 易错点最后扫一遍

1. ❌ NULL = NULL（应用 IS NULL）
2. ❌ WHERE 用聚集函数（应用 HAVING）
3. ❌ 候选码可以是空（候选码必须能唯一标识）
4. ❌ 主码可空（主属性不能空）
5. ❌ 外码必须不空（可空或等于被参照表主码）
6. ❌ BCNF 必须保持 FD（不一定）
7. ❌ 3NF 不能既无损又保持 FD（可以！算法 6.3）
8. ❌ 2PL 不会死锁（可能死锁）
9. ❌ 一次封锁法可能死锁（绝不死锁）
10. ❌ 可串行化 ⟺ 2PL（充分非必要）
11. ❌ 冲突可串行化 = 可串行化（充分非必要）
12. ❌ UNION 保留重复（自动去重，UNION ALL 才保留）
13. ❌ COUNT(*) 跳过 NULL（统计所有行）
14. ❌ COUNT(列) 统计所有（跳过 NULL）
15. ❌ 视图存数据（虚表，只存定义）
16. ❌ 自然连接必须用表名前缀（同名列只剩一个）
17. ❌ 一个外模式对应多个应用（一应用只能用一外模式）
18. ❌ 一个数据库可以有多个内模式（唯一！）
19. ❌ 外模式映像可保证完全独立（一定程度）
20. ❌ 静态转储无需日志（无需；动态才需）
21. ❌ 实体完整性允许主属性空（不允许）
22. ❌ MAC 是用户控制（系统强制）
23. ❌ ALTER TABLE 不能加约束（可以 ADD CONSTRAINT）
24. ❌ 全码就是主码（全码是所有属性才构成候选码）
25. ❌ 关系代数 ÷ 是基本运算（不是）
